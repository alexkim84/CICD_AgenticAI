# EARS 기반 테스트 데이터

## 구성

- 요구사항별 입력: `req_###_*_input.mat`
- 요구사항별 기대 출력: `req_###_*_baseline.mat`
- 전체 매핑 및 선정 근거: `test_case_manifest.json`
- 생성 스크립트: `scripts/generate_ears_test_cases.m`

각 MAT 파일의 신호는 스칼라 `timeseries` 객체이다. 신호 이름과 데이터형은 `crs_controller`의 루트 포트 선언을 따른다. 입력 보간 방식은 ZOH이며 샘플 시간은 `Ts (0.01 s)`를 사용한다.

## 생성 범위

비-Ubiquitous 요구사항 40개 중 요구사항 문장만으로 expected를 결정할 수 있는 27개에 대해 테스트 케이스를 생성했다.

- 생성: `#2`–`#9`, `#11`–`#18`, `#20`–`#26`, `#30`, `#36`, `#38`, `#39`
- 제외: `#10`, `#27`–`#29`, `#31`–`#35`, `#40`–`#43`

## 중요 사항

- baseline expected 값은 시뮬레이션 결과를 사용하지 않고 EARS 문장과 명시된 상수로 작성했다.
- `#12`와 `#16`은 버튼 해제 시 Short 요청을 기대하도록 요구사항을 그대로 반영했다. 현재 구현과 다를 가능성이 있으므로 실패 시 요구사항 또는 구현을 검토해야 한다.
- `#10`은 요구사항의 `reqMode.Resume`이 모델의 실제 enum 값 `reqMode.ResumeReq`와 불일치하여 제외했다.
- 수치, 전이 조건 또는 관찰 가능한 출력이 부족한 요구사항은 잘못된 expected 생성을 방지하기 위해 제외했다. 상세 사유는 매니페스트에 기록했다.
